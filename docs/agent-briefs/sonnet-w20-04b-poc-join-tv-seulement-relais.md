## Objectif (autonome)
Aujourd'hui `PlayHub.join` (`server-play/src/main/kotlin/castbridge/play/RoomRegistry.kt:201-209`) laisse entrer n'importe quel client avec un code et un pseudonyme ; la page `/play` est jouable ; seul l'hôte peut relayer des joueurs locaux (`android/core/src/main/kotlin/castbridge/core/quiz/online/ServerRoom.kt:249, 393`). Après ce cahier : (1) le **seul** client admis à entrer dans une salle est une **CastBridge-TV activée** présentant un ticket `cbp1` valide **et** son activation `cbx1` (même chaîne que `create`) ; (2) aucun navigateur n'atteint le jeu ; `/play` sert une page d'information statique ; (3) une TV **invitée** relaie **ses** téléphones comme l'hôte relaie les siens ; (4) la révocation fermée ne peut plus être désactivée par un réglage de staging ; un mode `off` explicite et visible existe pour le POC ; (5) une TV reliée en EDGE (plancher du propriétaire : 40 kbps ≈ 5 Ko/s) ne reçoit jamais une file d'états périmés devant une question ou une révélation : aujourd'hui chaque réponse envoie un `state` complet (≈ 5 Ko estimé à 8 joueurs) à chaque connexion, soit ≈ 40 Ko (≈ 8 s à 40 kbps) pour une rafale de 8 réponses.

## Étapes
1. **Rouge** (sortie collée) : `TvOnlyJoinTest.joinWithoutTicketIsRefusedBeforeLookup` contre `integration/agents` (aujourd'hui : un `join` sans ticket avec le bon code reçoit `welcome`).
2. `PlayConfig` : `webPlay` (`CASTBRIDGE_PLAY_WEB`, défaut faux ; « 1 » refusé au démarrage sauf `CASTBRIDGE_PLAY_DIRECT=1`) ; `maxRelayedPerTv` (`CASTBRIDGE_PLAY_MAX_RELAYED_PER_TV`, défaut 8, borné 1..8) ; `revocationsMode` (`CASTBRIDGE_PLAY_REVOCATIONS` = `on` | `off`, défaut `on` ; `off` refusé si `maxRooms` > 20) ; **`DIRECT=1` refusé si `CASTBRIDGE_PLAY_TRUSTED_PROXIES` est posé** ; les trois noms ajoutés à `ENV_NAMES`.
3. `PlayServer` : `revocationsReady = { cfg.revocationsMode == OFF || feed.usable() }` ; avertissement au démarrage et santé `"revocations":"disabled"` en `off` (via `HealthController`, zone additive si nécessaire) ; si `!webPlay` : toute requête `/play/ws`, `/play/act`, `/play/events`, `/play/state` portant un en-tête `Origin` non vide ⇒ 403 `{"error":"origine refusée"}` avant toute autre chose.
4. `PlayPageController(webPlay)` : si `!webPlay`, `/play` et `/play/j/<code>` ⇒ `info.html` (200, `Cache-Control: no-cache`, CSP `default-src 'none'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`) ; `play.js`, `play.css` ⇒ 404. Texte : « Les parties en ligne se jouent sur CastBridge-TV. Ouvrez le Quiz sur votre TV ; vos téléphones jouent par votre TV. »
5. Codec : `ClientMsg.Join.activation: String?` (additif, ASCII visible, ≤ `MAX_ACTIVATION`) ; un `join` qui porte `activation` peut atteindre `MAX_CREATE_BYTES` ; sans, 2 048 comme aujourd'hui ; `PlayCodecTest` étendu.
6. `PlayHub.join` (connexion **non assise**, `!webPlay`) dans cet ordre, fermé à chaque pas, rien consommé avant la fin : ticket (`verifier.check(c.ticket, real)`) ⇒ maintenance ⇒ `revocationsReady()` ⇒ `!used.seen(jti)` ⇒ `evaluator.evaluate(ticket.deviceCode, listOfNotNull(m.activation), real)` et édition ≠ `NONE` (sinon `used.use` : le ticket est brûlé, comme `create`) ⇒ **alors seulement** la recherche du code ; code faux ⇒ compteurs existants **plus** un compteur par identité (`BadCodeCounter` dédié, 30 / 5 min) ⇒ essai : `trialDays.count(identity) < PlayRules.TRIAL_GAMES_PER_DAY` (créations et entrées dans **le même** compteur) ⇒ connexions vivantes de cette identité (créées + rejointes) < `maxRoomsPerSubject` (essai : 1) ⇒ consommation (`used.use`, `trialDays.record`) ⇒ `attachAndForward` ⇒ si `welcome` : `e.room.grantRelay(c.id)` et l'identité est notée dans `RoomEntry`. Réponses : `PLAY_TICKET_REFUSED`, `PLAY_SCOPE_FORBIDDEN` (texte de `HostRights`/`PlayRules`), `PLAY_BAD_CODE`, `PLAY_BUSY`, maintenance. **Un appelant sans ticket valide reçoit la même réponse pour un code vivant et un code faux.** `webPlay=true` : code d'aujourd'hui, inchangé. `create` : inchangé.
7. `ServerRoom` (pur) : `Seat.relayer`, `Seat.relayedBy` ; `grantRelay(conn)` ; `relayJoin` accepté de l'hôte **ou** d'un siège relais, plafonné à `settings.maxRelayedPerTv` sièges par TV (`PLAY_ROOM_FULL`) en plus de la table ; `relay` ⇒ `FORBIDDEN` si `s.relayedBy !== sender` ; `disconnect`/`reattach` : présence des seuls sièges de cette TV ; un spectateur relais n'est pas purgé tant qu'il porte des sièges ; `hostWatch` : « derrière l'hôte » = `relayedBy === host` ; `safety()` : `localPlayers` = relayés par l'hôte, `remotePlayers` = les autres joueurs ; `setScope(false)` : les sièges relayés par une autre TV sont traités comme distants ; `kick` d'un siège relais retire aussi ses sièges relayés ; `Settings.maxRelayedPerTv = 8`.
8. **Coalescence « dernier état seulement »** : dans `FbConn.offer` et `WsConn.offer`, un message dont le type est `state` **remplace** le `state` encore non envoyé de la même connexion (le nouveau prend la place **en fin de file**, l'ancien est retiré ; les indices `idx` du repli restent croissants, un trou est permis) ; aucun autre type (`question`, `reveal`, `ack`, `ping`, `error`, `roomGone`, `replay`, `welcome`, `safety`) n'est jamais retiré ni réordonné ; le compte d'octets en file est corrigé ; le type est lu sans analyser tout le JSON (préfixe `{"t":"state"`, comme `TYPE` de `PlayFallbackController`).
9. Fixtures existantes : `webPlay = true` explicite ; toute la suite `:server-play:test` verte.
10. **Vert**, docs (`PLAY-PROTOCOL.md`, `PLAY-OPS.md` § 4.2, `backend/.env.play.example`), rapport.

## Cas limites
- Une connexion déjà assise qui envoie `join` : chemin actuel (`forward` ⇒ `relayJoin` de l'hôte ou du siège relais), aucun ticket redemandé. `resume` : inchangé (jeton de 128 bits), aucun ticket. Une TV qui rejoint sa propre salle (même `deviceHash`) ⇒ spectateur (règle existante). Ticket expiré pendant la partie : sans effet (contrôlé à l'entrée seulement, comme `create`).
