## Objectif (autonome)
Un module serveur **éteint par défaut** (`castbridge.activations.enabled`, allumé par `CASTBRIDGE_ACTIVATIONS_ENABLED=1`) qui tient l'**inventaire** des activations (essai, production, clés compactes), des TV qui les portent et des commandes du propriétaire, à partir de quatre sources (émissions du serveur, registre importé, journaux signés des outils, rapports des TV), les **réconcilie**, ouvre des **alertes douces**, garde un **historique immuable chaîné** et le sert à la console par une **API en lecture** auditée.

## Spécification
1. **V65** : tables du § 5.1 de la conception (`act_tool`, `act_journal_batch`, `act_key`, `act_tv`, `act_tv_device`, `act_event`, `act_event_head`, `act_alert`, `act_report`, `adm_read_audit`, `act_daily`, `act_tv_monthly`, `act_checkpoint`, `act_archive`, plus `act_policy(name PK, value, min, max, updated_at, updated_by)` pour les délais du § 3.5 et les cadences) ; index du § 5.1 ; aucune table existante modifiée.
2. **`TvRef`** : `tv_ref = hex(HMAC-SHA-256(act-ref.key, code normalisé)[0:8])` ; clé lue dans le dossier des secrets du module des licences (`castbridge.licenses.secrets-dir`) ; absente ⇒ module en 503 « Suivi des activations indisponible ». `act_event` et `adm_read_audit` ne portent **jamais** le code d'appareil en clair.
3. **`EventLog`** : ajout chaîné **dans la transaction de l'appelant** (modèle exact de `B/licenses/AuditLog.java` : tête `FOR UPDATE`, secondes entières, HMAC si `act-audit.key` existe, `verify()` par lots de 500) ; `idem_key` unique : rejouer une source ne double rien ; liste fermée des types (§ 5.1).
4. **`JournalVerifier`** + **`JournalService`** : enveloppe `cbx1` de type `journal` (§ 3.2 de la conception) décodée par le codec existant (`B/licenses/Envelope.java`, sans le modifier ; si le type inconnu est refusé par le décodeur, **analyser le corps ici** après vérification de signature) ; clé = une clé d'outil de `castbridge.licenses.trusted-keys` (ou la clé serveur), non révoquée (`lic_revocation`) ; `seq` de lot strictement croissant par `kid` ; `n` dense, `prev` = dernière empreinte connue ; une entrée de même `n` et d'empreinte différente ⇒ lot en **quarantaine** + alerte `JOURNAL_BROKEN` ; chaque entrée ⇒ évènement(s) et mise à jour d'`act_key`/`act_tv` ; le lot signé est gardé tel quel (`act_journal_batch.text`). Route `POST /api/v1/admin/activations/journal` (`ACT_JOURNAL_UPLOAD`) et formulaire web (w23-02). Vecteurs `journal-vectors.json` : lots valides, trou, réécriture, clé inconnue, clé révoquée, signature fausse, entrée de chaque type.
5. **Registre** : après chaque import par la route existante (`/admin/licenses/registry/import`), lire `lic_event` / `lic_ledger_import` par curseur (`LicenseAuditTap`, travail toutes les 60 s) ⇒ évènements `REGISTRY_IMPORT`, `ISSUED`, `TRANSFERRED`, `REVOKED_*` ; **lire** `lic_audit` par curseur ⇒ `LICENSE_CHANGED` (avant/après), `SEAT_RELEASED`.
6. **`ReportController`** : `POST /api/v1/activations/report` (§ 3.3) authentifié par le jeton d'appareil existant (même mécanisme que `PlayTicketController`) ; ≤ 4 jetons, 16 Ko ; chaque jeton vérifié avec `EnvelopeVerifier` (si non instanciable module des licences éteint : copier le strict nécessaire et le dire) ; facteurs ≠ code ⇒ jeton ignoré + alerte ; empreinte calculée, jeton **jeté** ; liaison `device.id` ↔ `tv_ref` ; évènements seulement **si changement** ; réponse `{next, revocations?}` (`next` lu dans `act_policy`, 0 = coupé). Interface publique **`ActivationObserver.observe(deviceId, tokens, state, via)`** utilisée aussi par le relais coursier (w23-04) et, plus tard, par `wallet/sync` (W22).
7. **`Reconciler`** : à chaque arrivée pour les objets touchés, et `@Scheduled(cron = "0 50 3 * * *", zone = "Africa/Douala")` pour tout ; codes du § 3.5 avec délais d'`act_policy` ; **aucune action automatique**.
8. **API en lecture** (§ 4.2) : `/api/v1/admin/activations/{activations, activations/{fp}, tvs, tvs/{deviceCode}, dashboard, alerts, tools, changes, export, checkpoints}` ; curseurs `(clé de tri, id)`, `limit` ≤ 500, aucun `OFFSET` ; `changes?after=&wait=` (≤ 25 s, `DeferredResult`, 1 par session, 20 au total) ; export CSV (RFC 4180, même style que `LicenseCsv`) et JSONL en flux, ≤ 200 000 lignes ; les mêmes services sont publiés pour w23-02 (classe de service, pas seulement le contrôleur).
9. **Contrôle d'accès** : `ActPermissions` (table du § 6.2, correspondance par `Role` **sans modifier** `Role.java`) ; jeton d'API = OWNER ; permissions sensibles ⇒ TOTP comme le module des licences (réutiliser sa vérification, sans la copier si elle est publique).
10. **`ReadAudit`** + `ReadAuditInterceptor` : **une ligne par lecture** de liste, fiche, tableau de bord, alerte, export, point de contrôle (acteur, rôle, canal `web|api|phone`, route, filtres normalisés ≤ 300 car. sans secret, cible `tv_ref` ou `fp8`, lignes rendues, export oui/non), chaînée comme `EventLog` ; l'interrogation longue `changes` n'écrit qu'**une** ligne par ouverture de session de suivi (pas une par tour).
11. **`Snapshots`** : `act_daily` chaque nuit (00:05 Douala), `act_tv_monthly` le 1er ; **`Checkpoints`** : 00:10 Douala, têtes des deux chaînes + compteurs, signés Ed25519 si `act-checkpoint.key` existe (sinon HMAC, sinon SHA-256) ; `tools/activations/verify_export.py` vérifie un export + points de contrôle hors ligne.
12. **`Archiver`** : `POST /admin/activations/archive` (OWNER, TOTP, motif) : lignes de plus de 24 mois ⇒ `act-archive/<table>-AAAA-MM.jsonl.gz` + `act_archive` ; jamais automatique ; `act_report` purgé à 90 j (`@Scheduled`).
13. **`ErasureHook`** : quand le droit à l'effacement du module des licences anonymise un client, effacer `act_tv.device_code` des TV de ses postes + évènement `ERASED` (si le module ne publie pas d'évènement, un travail compare `lic_seat.anonymized` par curseur ; le dire).
14. **`ConsoleSession`** (option A de D-W23-3, **désactivée par défaut**, `castbridge.activations.console-sessions=false`) : défi 32 hex (120 s, usage unique) signé par la clé d'outil `phone` ⇒ jeton porteur 15 min, portées `ACT_READ` + `ACT_JOURNAL_UPLOAD`, 10 défis / h / `kid`.
15. **Débits** du § 6.5.

## Critères d'acceptation (mutations au rapport)
- **Cohérence d'inventaire** : scénario synthétique (bureau émet 3 essais + 1 compacte, téléphone émet 2 productions et 1 `open_all`, serveur émet 1 production, 5 rapports TV dont 1 activation non déclarée et 1 clonée) ⇒ chaque activation dans le bon état, chaque alerte attendue **et aucune autre** ; rejouer **toutes** les sources dans un autre ordre, deux fois ⇒ mêmes tables (`act_key`, `act_tv`, `act_alert`) et aucun évènement en double (mutation : retirer l'unicité d'`idem_key` ⇒ échec).
- **Conservation de la chaîne** : `verify()` vrai après 10 000 évènements ; modifier une ligne, en retirer une, tronquer la queue ⇒ `verify()` désigne la ligne (mutation : ne pas verrouiller la tête ⇒ le test de concurrence à 16 fils fourche la chaîne).
- **Journal** : chaque cas de `journal-vectors.json` ⇒ résultat attendu ; trou ⇒ `JOURNAL_GAP` après le délai (horloge injectée) ; réécriture ⇒ quarantaine (mutation : ne pas vérifier `prev` ⇒ échec).
- **Rapport** : jeton d'un autre appareil ⇒ ignoré + alerte ; rapport identique répété ⇒ aucun évènement ; jeton en clair **absent** de toute table et de tout journal applicatif (recherche de `cbx1.` dans la base H2 et dans les journaux capturés).
- **Contrôle d'accès** (matrice complète, une assertion par route × rôle × TOTP) : READONLY ne peut ni exporter ni classer ; SUPPORT accuse mais ne classe pas ; OWNER sans TOTP ne peut pas exporter quand TOTP est exigé ; module éteint ⇒ 404 ; jeton d'API ⇒ OWNER et **audité** sous `api-token`.
- **Audit des lectures** : chaque route de lecture écrit exactement une ligne (mutation : retirer l'intercepteur d'une route ⇒ le test « toute route `/api/v1/admin/activations/**` est auditée », qui énumère les routes par réflexion, échoue).
- **Aucune écriture dans `lic_*`** : test qui compare le contenu des tables `lic_*` avant/après la suite.
- **Effacement** : client effacé ⇒ code d'appareil absent d'`act_tv`, chaîne toujours vérifiable.
- **Volumes** : 100 000 activations et 1 000 000 d'évènements synthétiques sur H2 ⇒ page de liste et fiche TV < 200 ms (mesure locale indicative, dite au rapport) ; aucun `COUNT(*)` sur `act_event` dans le chemin d'affichage.
- Outillage existant : H2 en mode MySQL + Flyway (`ApiTestBase`) ; MySQL 8.4 par `MySqlContainerTest` pour la concurrence de la chaîne (sauté sans Docker : dire s'il a tourné). Aucune dépendance nouvelle.

## À ne pas faire
- Stocker ou journaliser un jeton `cbx1`, une clé compacte, un défi complet, un jeton d'appareil ou d'API ; révoquer, suspendre ou libérer quoi que ce soit automatiquement ; écrire dans les tables du module des licences ; suivre des soldes de jetons.
