## Objectif (autonome)
Que **chaque** action d'émission des outils hors ligne du propriétaire (activation, clé compacte, remise Bluetooth et son résultat, commande `support`/`unlock`/`open_all`, refus) soit écrite dans un **journal numéroté, chaîné et signé** par la clé de l'outil, exportable sans réseau, et que le serveur (w23-01) puisse le vérifier ; et que le téléphone du propriétaire ouvre le suivi du serveur **sans** que l'application propriétaire n'obtienne de permission réseau (D-W23-3 = B, défaut).

## Fichiers possédés
- **Nouveaux** : `android/core/src/main/kotlin/castbridge/core/owner/ToolJournal.kt` (entrées, chaîne `h_n = SHA-256(h_{n−1} | ligne)`, numérotation dense, persistance par `SafeFile`, construction de l'enveloppe `cbx1` de type `journal` avec l'émetteur existant `Envelope`, découpage en lots ≤ 500 entrées / 128 Ko, QR en série ≤ 2 Ko) + `android/core/src/test/kotlin/castbridge/core/owner/ToolJournalTest.kt` (rejoue `tools/activation/journal-vectors.json`) ; `android/owner/src/main/kotlin/castbridge/owner/{JournalExport,OpenTracking}.kt` ; `tools/activation-desktop/src/main/kotlin/castbridge/desktop/JournalCommands.kt` + test.
- **Zone additive** : `C/owner/PhoneConsole.kt` (appels `journal.record(...)` à côté des `audit.append(...)` existants : `issue`, `license`, refus ; aucune logique changée) ; `C/owner/OwnerChannel.kt` ou l'appelant de la remise Bluetooth (entrée `deliver` / `command` avec le `RESULT` de la TV) ; `DK/Desk.kt` (`compact(...)` et `issue(...)` journalisent) et `DK/Cli.kt` (commande `journal-exporter [--depuis n] [--sortie fichier.cbj]`, aide en français) ; `OL/ConsoleActivity.kt` : **un seul crochet** `protected open fun extraTabs(): List<Pair<String, @Composable () -> Unit>> = emptyList()` ajouté à la rangée d'onglets, **sans autre changement** (l'APK grand public de CastBridge embarque `ownerlib` : il doit rester identique en comportement) ; `OW/OwnerActivity.kt` (surcharge `extraTabs`).
- **Interdit** : `android/receiver/**`, `android/sender/**` (hors vérification de compilation), `backend/**`, le format du registre (`LicenseEvent`, `LicenseBook` : inchangés), les vecteurs `tools/activation/test-vectors.json` (inchangés), toute permission dans `android/owner/src/main/AndroidManifest.xml` en mode B.

## Spécification
1. **Format** : exactement le § 3.2 de la conception (enveloppe `cbx1`, `type=journal`, `target=any`, `seq` = n° de lot par clé, corps `tool`, `app`, `from`, `to`, `prev`, lignes `e=`) ; types d'entrée `issue`, `compact`, `deliver`, `command`, `license`, `revoke`, `transfer`, `refused` ; **jamais** le jeton, la clé compacte, le défi complet (8 hex de son SHA-256), le code de déverrouillage. Les octets produits doivent être **identiques** à ceux des vecteurs de w23-01 pour les mêmes entrées.
2. **Téléphone (mode B, défaut)** : onglet « Journal » (existant) enrichi par `extraTabs` ou par un panneau dans l'onglet : nombre d'entrées non exportées, date du dernier export, **« Exporter le journal signé »** (console déverrouillée exigée : la signature utilise la clé du coffre) ⇒ fichier `Download/castbridge-journal-<kid8>-<from>-<to>.cbj` (MediaStore), **partage** Android (`ACTION_SEND`, type `application/octet-stream`), **QR** en série pour les petits lots ; rappel après 7 j sans export ; bouton **« Ouvrir le suivi »** = intention `ACTION_VIEW` vers `https://bridge.sti-cm.com/admin/activations` (aucune permission requise ; l'URL est une constante de build `OWNER_TRACKING_URL`).
3. **Bureau** : `journal-exporter` signe avec la clé du bureau (code de déverrouillage saisi comme pour les autres commandes, jamais en argument) ; `journal-etat` affiche le dernier `n`, la dernière empreinte et les entrées non exportées ; la fenêtre graphique reçoit un bouton « Exporter le journal… » dans l'onglet existant le plus proche (sinon, le dire et laisser la ligne de commande seule).
4. **Remise et commandes** : chaque `ACTIVATION` envoyée par Bluetooth ⇒ entrée `deliver way=bt tv=ok|refused:<raison>` ; chaque `COMMAND` ⇒ entrée `command` avec `power`, `action`, `days`, `clamped`, `result`.
5. **Rétrocompatibilité** : un journal absent (première version) commence à `n = 1`, `prev = 0×64` ; les émissions antérieures restent connues du serveur par le registre.

## Annexe — option A (seulement si le propriétaire choisit D-W23-3 = A)
Permission `INTERNET` **dans `android/owner` seulement** ; `network_security_config.xml` limité à l'hôte du serveur avec épinglage de clé publique (deux broches : courante + secours) ; client de session signée (`GET …/console/challenge`, signature du défi par la clé du téléphone, `POST …/console/session` ⇒ jeton 15 min, gardé en mémoire seulement) ; téléversement automatique des lots non envoyés ; onglet « Suivi » en lecture (tableau, alertes, recherche par code saisi ou lu par `DEVICE_INFO`, fiche TV) avec bandeau « à jour il y a X » ; **aucune** action sensible. Tests : aucune requête hors de l'hôte épinglé ; session refusée console verrouillée ; jeton jamais écrit sur disque.

## Critères d'acceptation (mutations au rapport)
- `ToolJournalTest` : tous les cas de `journal-vectors.json` (mêmes octets) ; 10 000 entrées ⇒ chaîne vérifiée ; modifier une entrée persistée ⇒ détecté au chargement (mutation : ne pas chaîner `prev` d'un lot à l'autre ⇒ échec).
- Aucun secret : recherche, dans les fichiers produits par les tests, de `cbx1.` hors de l'enveloppe du journal elle-même, des 165 caractères d'une clé compacte, d'un défi complet ⇒ rien.
- `PhoneConsole` : une émission, un refus, une licence ⇒ trois entrées, dans l'ordre, et `AuditChain` inchangée dans son contenu.
- Mode B : le manifeste fusionné de `:owner` ne contient **aucune** permission nouvelle (test de manifeste ou vérification `aapt dump permissions` au rapport) ; `:sender:assembleDebug` passe et l'entrée super-administrateur se comporte comme avant (aucun onglet nouveau sans surcharge).
- Bureau : `journal-exporter` puis vérification par le vérificateur Kotlin de test ⇒ valide ; code de déverrouillage jamais dans le journal ni dans l'historique de commande (test existant du bureau étendu).

## À ne pas faire
- Ajouter une permission à l'application propriétaire en mode B ; mettre un écran nouveau dans `ownerlib` ; modifier le format du registre ou les vecteurs d'activation ; exporter un jeton, une clé compacte ou un défi complet.
