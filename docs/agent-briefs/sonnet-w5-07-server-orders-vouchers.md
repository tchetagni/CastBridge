## Étapes
1. `ShopRequestVerifier.verify(text, deviceToken): VerifiedProof` : `ShopRequest.parse` (w5-05) ; `activation` : `EnvelopeVerifier` avec anneau `TrustedKeys` + délégations connues (ticket `<délégation>|<activation>` : séparer, vérifier la délégation puis l'activation avec la clé de l'agent) ; cible = empreintes de la demande (k parmi n) ; `kind`, `license`, `seat`, `counting` (plafond `usage` : calculer `usageEnd` comme `ActivationService.parseDuration` et comparer à `now` ; **sans** horloge de la TV : le serveur fait foi) ; `installPub` ; `rentals` ; état : `PRODUCTION_ACTIVE | PRODUCTION_ENDED | TRIAL | NONE`. Erreurs : `PROOF_MISSING`, `PROOF_INVALID(reason)`, `PROOF_DEVICE_MISMATCH`, `INSTALL_KEY_MISSING`.
2. `OrderService` : `quote(proof, item)` (politique serveur : essai ⇒ `orderable=false` « clé de production requise » ; production terminée ⇒ seulement `cle-production` par bon ; prix de la grille **signée** déposée (`GET /api/v1/catalog/prices` : relire le fichier, vérifier la signature avec `owner-public-keys`) ; bouquet via `RentalContractService.canRent`) ; `create(proof, item, qty, channel, idemKey, voucherCode?)` : `shop_order` ; avec bon ⇒ `VoucherPayment.settle` puis `fulfil` **dans la même transaction** ; sans ⇒ `AWAITING_PAYMENT`, `expires_at = now + order-ttl-hours`, instructions FR ; `fulfil(order)` : `RENTAL` ⇒ `RentalContractService.createOrRenew` ; `TOKENS` ⇒ `TokenCrediting.credit(license, n, "order:<ref>")` + bon de jetons pour la TV ; `KEY` ⇒ `ActivationService.issue(actor=SHOP, licenceId = celle de la preuve ou « auto » si aucune, subject tv, deviceRequest, production, usageDays = jours du bon)` ; `get`, `delivered`, `cancel` (seulement `AWAITING_PAYMENT`), `expire` (tâche : `AWAITING_PAYMENT` > TTL ⇒ `EXPIRED`), `me(proof)` (commandes 90 j, contrats actifs, solde et bons non livrés via `TokenCrediting.pendingGrants`, reçus).
3. `PaymentMethod { PaymentResult settle(Order, PaymentProof) }` : `VoucherPayment` (hash du code ; `ISSUED|SOLD` ; lot non révoqué, non expiré ; **article du bon = article de la commande** ; `redeem` sans commande : crée la commande de l'article du bon ; compteur d'essais : 5 par appareil et par heure, puis verrou 1 h ; **par licence aussi** ; chaque échec journalisé avec le hash tenté tronqué, jamais le code), `AgentCashPayment` (voir 5), `OwnerGrantPayment` (motif obligatoire, utilisé par w5-09 avec TOTP et par w5-06 pour réémission/essai). Toute `shop_payment` est `UNIQUE(method, ref)`.
4. `VoucherService` : `importBatch(signedText, importedBy)` (vérifie la signature du propriétaire, insère `voucher_batch` + `voucher` par hash ; refuse un lot déjà importé ou un serial connu), `revokeBatch(id, reason)`, `revokeVoucher(serial, reason)`, `stockForAgent(kid)`, `expireDue()`.
5. `AgentShopService.confirm(delegationToken, ledgerEntryText)` : vérifie la délégation (w4-16) et l'entrée signée (chaîne vérifiée **à la synchronisation** ; ici : signature + `item = commande|<ref>|<montant>`), `may_confirm_orders`, quotas (`max_confirm_xaf_per_day`, `maxSales`), commande `AWAITING_PAYMENT` et `amount == montant` ⇒ `AgentCashPayment.settle` ⇒ `fulfil` ; stocke `agent_order_confirm` ; idempotent (même `agent, seq` ⇒ même réponse) ; réponse `{accepted, reason, order: {ref, item, amount, deviceCodeMasked}}`. `GET /agent/orders/{ref}` (détail masqué avant encaissement) ; `GET /agent/vouchers/stock`. Les mêmes entrées arrivant par `/api/v1/agent/sync` (w4-16) doivent être traitées **aussi** : exposer `AgentShopService.onLedgerEntry(entry)` que w4-16 appellera (si w4-16 n'a pas de point d'extension, le demander dans le rapport ; en attendant, une tâche toutes les 5 min relit `agent_ledger` pour les `commande|` non traitées).
6. `ReceiptService.issue(order)` : texte FR (article, durée/quantité, montant, date, moyen « espèces (point focal <name>) » ou « bon de recharge <serial> », code TV masqué, contact D7 depuis la config `castbridge.shop.contact` (vide ⇒ ligne omise)), code `R-XXXX-XXXX` (w4-17 `ReceiptCode`), signature `LicenseKeyring.sign` ; `GET /receipts/{code}` public (le texte ne contient aucune donnée personnelle).

## Cas limites
- Bon `loc-<b>` redimé depuis une TV **en essai** : refus « clé de production requise » ; le bon reste `SOLD` (non consommé).
- Bon `cle-production` redimé depuis une TV déjà en production active : accepté = **prolongation** (nouvelle activation de production, même licence, `usageDays` du bon ajoutés à partir de la fin actuelle : réutiliser la logique `extend` de `LicenseService` si elle existe, sinon émettre une clé qui commence à la fin actuelle ; le dire).
- Commande espèces dont la TV change de clé entre-temps : la preuve est **re-vérifiée** à l'exécution (`fulfil`) ; si elle ne vaut plus, la commande passe `PAID` mais `fulfilment` attend la prochaine `GET` avec une nouvelle demande (`needsFreshRequest = true`).
- Grille absente ou non signée : `quote` ⇒ 503 « tarifs indisponibles » ; aucun ordre possible.
